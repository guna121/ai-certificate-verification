# CertVerify — AI Certificate Verification System

A full-stack project that lets colleges and companies verify whether a
certificate (PDF/JPG/PNG) is genuine, suspicious, or revoked, using OCR,
QR-code detection, SHA-256 hashing, and a rule-based risk score.

```
certificate-verification/
├── backend/
│   ├── main.py            FastAPI app + all API routes
│   ├── database.py        SQLite connection + schema + demo data
│   ├── models.py          Pydantic request/response schemas
│   ├── auth.py            Password hashing (PBKDF2) + JWT auth
│   ├── verification.py    OCR / QR / hash / risk-score pipeline
│   ├── requirements.txt
│   └── uploads/           (created automatically, currently unused for storage)
└── frontend/
    ├── index.html         Home / landing page
    ├── login.html
    ├── signup.html
    ├── dashboard.html     Role-aware dashboard
    ├── verify.html        Upload + AI verification page
    ├── recruiter.html     Recruiter-focused verification page
    ├── history.html       Verification history
    ├── admin.html         Admin panel (certificate registry, stats)
    ├── style.css
    └── script.js
```

## 1. Install Python

You need **Python 3.10+**.

- **Windows**: download from https://www.python.org/downloads/ and check
  "Add Python to PATH" during install.
- **macOS**: `brew install python3` (requires Homebrew), or download from
  python.org.
- **Linux (Debian/Ubuntu)**: `sudo apt update && sudo apt install python3 python3-pip python3-venv`

Verify it worked:
```bash
python3 --version
```

## 2. Install the OCR engine (Tesseract) — required

The verification pipeline calls the Tesseract OCR engine as an external
program (via `pytesseract`), so it must be installed separately from the
Python packages.

- **Windows**: install from https://github.com/UB-Mannheim/tesseract/wiki,
  then make sure the install folder (e.g. `C:\Program Files\Tesseract-OCR`)
  is added to your PATH.
- **macOS**: `brew install tesseract`
- **Linux (Debian/Ubuntu)**: `sudo apt install tesseract-ocr`

Verify it worked:
```bash
tesseract --version
```

### Optional: PDF support

To verify **PDF** certificates (not just JPG/PNG) you also need Poppler,
used by the `pdf2image` package to render the first PDF page as an image:

- **Windows**: download Poppler binaries and add the `bin` folder to PATH.
- **macOS**: `brew install poppler`
- **Linux**: `sudo apt install poppler-utils`

If Poppler isn't installed, JPG/PNG verification still works fine — only
PDF uploads will show a friendly error asking you to install it.

## 3. Install backend dependencies

```bash
cd certificate-verification/backend
c

# Activate the virtual environment:
source venv/bin/activate        # macOS/Linux
venv\Scripts\activate           # Windows

pip install -r requirements.txt
```

## 4. Create the database

You don't need to run a separate migration script — the SQLite database
(`certverify.db`) and all tables are created **automatically** the first
time the backend starts, including a demo institution and a demo
certificate (`CERT-2024-0001`) so you have something to test against
immediately.

If you ever want to reset everything, just delete the generated file:
```bash
rm backend/certverify.db
```
It will be recreated fresh the next time you start the server.

## 5. Run the FastAPI backend

From inside `backend/` (with the virtual environment active):
```bash
uvicorn main:app --reload --port 8000
```
You should see log lines confirming the database initialized and the
server is running. Leave this terminal open.

- API base URL: `http://127.0.0.1:8000`
- Interactive API docs (auto-generated by FastAPI): `http://127.0.0.1:8000/docs`
- Health check: `http://127.0.0.1:8000/api/health`

## 6. Open the frontend

The frontend is plain HTML/CSS/JS — no build step needed. Two easy options:

**Option A — just open the file:**
Double-click `frontend/index.html` (or right-click → Open with your browser).

**Option B — serve it with Python (recommended, avoids browser file:// quirks):**
```bash
cd certificate-verification/frontend
python3 -m http.server 5500
```
Then visit `http://127.0.0.1:5500` in your browser.

> The frontend talks to the backend at `http://127.0.0.1:8000` (see the
> `API_BASE` constant at the top of `frontend/script.js`). If you run the
> backend on a different host/port, update that constant.

## 7. Test login / signup

1. Open `signup.html`, choose a role (**Admin** is useful for testing the
   full feature set), fill in the form, and submit.
2. You'll be logged in automatically and redirected to `dashboard.html`.
3. Try logging out (sidebar button) and logging back in via `login.html`
   with the same email/password.

Passwords are hashed with PBKDF2-HMAC-SHA256 (200,000 iterations) plus a
random per-user salt before being stored — plaintext passwords are never
saved or logged.

## 8. Test certificate verification

The database is seeded with one demo certificate:

| Certificate ID  | Student Name  | Status |
|------------------|---------------|--------|
| `CERT-2024-0001` | Demo Student  | active |

**Quickest way to test the full pipeline:**

1. Create a simple image (in any image editor, or even MS Paint / Preview)
   containing the text `CERT-2024-0001` somewhere on it, and save it as
   `test-cert.png`.
2. Log in, go to **Upload & Verify**, upload that image.
3. You should see a **✅ Verified** or **⚠️ Needs Review** result (the
   first upload for a certificate stores its hash as the "original," so
   verifying the *exact same file* a second time should show a cleaner
   Verified result).
4. Try uploading an unrelated image (no matching certificate ID) — you
   should see a **❌ Suspicious** result with a high risk score.

**To test Admin + Revoke:**

1. Sign up (or log in) as an **Admin**.
2. Go to **Admin Panel → Register a genuine certificate**, add a new
   certificate ID (e.g. `CERT-2024-0099`).
3. Make an image containing that text and verify it — it should come
   back Verified.
4. Click **Revoke** next to that certificate in the registry table, then
   verify the same image again — it should now come back **🚫 Revoked**.

**To test the Recruiter flow:** sign up as a **Recruiter**, go to
**Recruiter Check**, and upload any certificate the same way — you'll get
a hiring-oriented recommendation alongside the risk score.

## How the verification pipeline works

```
Upload Certificate (PDF/JPG/PNG)
        ↓
OpenCV preprocessing + Tesseract OCR extracts text
        ↓
Regex reads the Certificate ID from the extracted text
        ↓
OpenCV's built-in QRCodeDetector checks for/decodes a QR code
        ↓
SHA-256 hash generated from the raw uploaded file bytes
        ↓
Certificate ID (and QR data) looked up against the `certificates` table
        ↓
Rule-based risk score (0–100) calculated from: DB match, file-hash match,
QR presence/match, OCR confidence
        ↓
Final result: ✅ Verified / ⚠️ Needs Review / ❌ Suspicious / 🚫 Revoked
        ↓
Every attempt is logged to `verification_history` for the History page
```

## Notes on security & logging

- Passwords are never logged, only hashed and stored.
- JWT tokens are never logged.
- Certificate file contents/OCR text are not written to logs — only
  high-level events (e.g. "verification complete: result=verified") are
  logged, for debugging and auditing without exposing sensitive content.
- The `SECRET_KEY` in `auth.py` is hard-coded for demo convenience; in any
  real deployment set it via the `CERTVERIFY_SECRET_KEY` environment
  variable instead.
